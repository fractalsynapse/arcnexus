# ArcNexus charter

ArcNexus helps a human architect develop software through components with clear
responsibilities, interfaces and observable acceptance. Its first major success
is using the product to improve itself under the same authority model it applies
to other projects.

The architect owns purpose, boundaries, and accepted interfaces. A director turns
a goal into a sequence of accountable milestones. Component stewards produce the
changes. The host captures and enforces authority, records evidence, and carries
an independently verified candidate through the configured delivery path.
Differences between steward claims, observed checks, review and integration stay
visible. A candidate cannot grant itself permission or weaken its active acceptance.

Cordis plugins are the unit of composition. Keep each public interface with its
implementation, documentation, tests and owner-specific scripts. Use the least
code that meets the accepted outcome. Define each responsibility once and let
consumers use that definition directly. [Project contract](interface/arcnexus-project.md)

First make the host CLI useful for inspecting Codex context and running engineering
tasks. Prove real self-development on that path before expanding into self-directed
workdays, API or UI gateways, or broader portfolio and release capabilities.
Those capabilities should share the same application services.
