# Recover a prepared checkpoint

Rerun the same task or standing round after staging advances. Execution can
prepare a fresh worktree on the existing issue branch when the earlier
checkpoint is confirmed and staging descends from the recorded base. Its
recovery commit retains both the secured checkpoint and the new staging parent.
The Director's accepted plan and the recorded activity position can continue.
Assembled checks and independent review apply to the newly assembled candidate.

Execution checks the local and remote issue ref before retaining the recovery
commit. A changed worktree, overlapping path, authority or guidance change, or
existing publication holds recovery with the original branch and evidence.
Proposed contract edits in the registry may advance staging when registry
policy and every locked entry are unchanged. The earlier checkpoint and staging
changes must both survive the merge byte for byte.

An interrupted checkpoint push reconnects to the ordinary checkpoint
reconciliation path. A previously recorded publication uses
[Delivery recovery](../../delivery/contract.md). Verification still requires
a current candidate and staging parent.
