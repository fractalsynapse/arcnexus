# Architecture application

The [contract](contract.md) governs capture, request construction and the
Architect assessment. The application uses the existing Agent, HostTask,
Coordination journal, Clarifications and normal Workflow delivery. It introduces
no separate proposal store or simulated source adapter.

`architecture update` assesses accepted direction and retained findings. Feedback
focuses that assessment. A justified no-change result retains its source links.
A proposal records purpose, consequences, implementation outcomes, baseline and
exact file contents, including any registry digest amendment, before human review.
Approval binds those exact bytes and intent. Unknown approval remains pending;
changed proposals and baselines require renewed review.

After approval, Direction plans prerequisite implementation through the ordinary
steward lifecycle. The host applies the approved guide batch to that same candidate
before assembled verification and independent review. Model checked edits cannot
perform this protected application. A completed delivery supplies a fresh capture
to subsequent work; the active capture remains immutable.

Implementation of this approved capability is bootstrap work in #631. Deterministic
checks, hosted CI and real phase acceptance are reported separately.

documentation does not establish runtime support or authorize new mappings.

`check` handler, with applicability values `owner-format-files` and
`owner-lint-files`, respectively. They invoke the existing `format:check`
and `lint` npm commands with the captured owner argument, existing configuration
and read-only flags. Applicable shared `repository-types` and

model and public tooling boundaries. Invalid declarations, unresolved operation,
role, profile or standard references, missing prerequisite implementations and
unavailable handlers prevent activation. Recognizing a declaration is insufficient
to make its runtime implementation available. Inspection and activation resolve
the same captured operation definitions, prerequisites and exact handler schemas;
empty operation lists remain empty and missing activities remain unavailable.

## Supplier handoff and progression

The accepted `quality-foundation` contribution supplies selection and command
behavior. Architecture supplies operation-model support and declaration validation
in `quality-architecture`. The existing `quality-execution` milestone consumes
both through public entries and enforces current, independent evidence for every
applicable captured operation through the existing HostTask/check/journal path.
Its ownership validation, selection parity and evidence identity obligations are
specified in [quality-identity-boundary](quality-identity-boundary.md).

An empty formatting selection and an empty lint selection each require their own
scope and precise reason. Suite absence affects only `owner-tests`; unavailable
required support cannot become successful inapplicability. Testing retains
deliberately declared expected-red owner tests separately from passing applicable
quality checks. Implementation requires passing applicable checks. Missing, stale
or unrelated evidence, including another operation's success, cannot satisfy an
obligation or permit progression. Ordinary failures return exact diagnostics to
the same caller for milestone-local repair while preserving receipts, complete
answers, failed observations and unaffected evidence.

The accepted `quality-verification` milestone consumes actual assembled evidence
and supplier results for its positive and negative regressions. These engineering
observations leave all five captured assembled requirements mandatory:
`repository-build`, `repository-types`, `repository-format`,
`repository-lint` and `repository-tests`. The host retains assembled verification,
one independent candidate-bound verdict, required CI and PR review, and staging
delivery. Main and production actions remain separate. Execution-path changes
restart live qualification; this prerequisite documentation establishes no
qualification streak or delivery result.
