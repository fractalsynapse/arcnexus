# Make operation authority and check outcomes explicit

Review the proposed operation model as an exact architecture change before adoption. Give operations clear nonblank purposes shared by discovery, inspection and activation. Keep tool identity, input schema and trusted dispatch consistent.

Use explicit activity operation bindings as the source of tool authority and completion-check configuration. Keep execution profiles focused on provider settings. Preserve typed parameters, confinement, independent assembled checks and historical authority.

Review removal of operation categories and host preflight applicability together with affected contracts, mappings and guidance. Resolve the documented change from no-suite inapplicability to command-owned failure explicitly. Preserve trusted post-run scope validation for owner quality checks; a zero exit without required valid scope evidence cannot pass.

## Observable success

- Distinct operations advertise useful purposes while identical bindings resolve identical arguments.
- Unmapped calls and verification references are refused.
- Revised commands report missing inputs through their actual diagnostics.
- Missing, malformed or foreign scope reports fail validation.
- Changed evidence requirements cannot reuse older acceptance.
