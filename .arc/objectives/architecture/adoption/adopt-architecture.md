# Adopt approved architecture coherently within a run

Resolve one validated operating model with source provenance for context, ownership, operations, profiles and completion checks. Preserve explicit empty lists and approved replacement semantics; omitted values must not silently delete records or expand authority.

After an exact approved update and required implementation validation, adopt the model at a recorded activity boundary. Complete or cancel an in-flight activation first. Regenerate the next activation's context, ownership, tools and checks together. Earlier activations retain their original authority and observations.

Revalidate retained work, checkpoints and affected evidence before continuation. Missing handlers, incompatible ownership or unavailable runtime prerequisites produce precise diagnostics rather than partial adoption. Candidate files cannot authorize their own execution.

## Observable success

- An approved implemented operation becomes available to the next eligible activity in the same logical run.
- Removed operations, changed ownership and explicit empty lists take effect consistently in inspection and activation.
- Stale approval, missing handlers and interrupted adoption preserve a recoverable position without mixed model versions.
- Original acceptance and historical evidence remain readable.
