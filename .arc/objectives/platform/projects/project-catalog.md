# Keep project selection verified and isolated

Register projects through authorized canonical repositories and retain verified commits and credential references. Provision absent managed checkouts only within trusted bindings. Keep read credentials, publication grants and execution assignments distinct; imported project declarations cannot replace trusted runtime composition.

Refresh catalog revisions without changing active executions' captured authority or losing previously accepted revisions. Carry selected project identity through navigation, resource requests, commands, caches and subscriptions. Show registration separately from reachability.

Removing a project disables selection and routing while retaining Git and run evidence. Close old subscriptions on project switches and present an explicit unselected state when no reachable project remains.

## Observable success

- Public and private imports verify exact repository and commit identity and refuse unauthorized bindings.
- Secrets remain outside URLs, event payloads and agent inputs.
- Project switching cannot reuse another project's data or cursors.
- Refresh and removal preserve retained execution provenance and evidence.
