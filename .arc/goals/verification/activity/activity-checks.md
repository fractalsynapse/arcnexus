# Make activity verification declarative and truthful

Select required activity verification through validated operation bindings. Resolve declared defaults and explicit typed overrides consistently for direct invocation and automatic completion. Arguments remain data; identity, confinement and authority remain trusted-host responsibilities.

Require applicable completion checks before progression. Expected-red evidence identifies the exercised assertion and intended missing behavior; dependency, compiler and fixture failures cannot establish it. Keep passing, failing, skipped and inapplicable observations distinct.

Reuse evidence only when relevant inputs, parameters, bindings, runtime and environment match. Unknown applicability requires fresh evidence. Local claims cannot replace required assembled verification.

## Success measures

- Different activities reuse an operation with distinct validated selectors and identical resolution across invocation paths.
- Invalid overrides and explicit empty selections receive precise diagnostics.
- Expected-red scenarios reject setup failures as behavioral proof.
- Changed parameters or relevant inputs prevent stale reuse, and required checks govern progression.
