# Make operation authority and check outcomes explicit

Review the proposed operation model as an exact architecture change before adoption. Give operations nonblank purposes shared by discovery, inspection and activation. Preserve consistent tool identity, input schema and trusted dispatch.

Use explicit activity bindings for tool authority and completion checks, with profiles focused on provider settings. Preserve typed parameters, confinement, independent assembled verification and historical authority.

Review category and applicability removal with affected contracts, mappings and guidance. Explicitly resolve the change from no-suite inapplicability to command-owned failure. Preserve trusted post-run ownership validation for quality checks: zero exit without required valid scope evidence cannot pass.

## Success measures

- Distinct operations advertise useful purposes; identical bindings resolve identical arguments.
- Unmapped calls and verification references are refused.
- Commands report missing inputs through actual diagnostics.
- Missing, malformed, empty or foreign scope reports fail validation.
- Revised evidence requirements cannot reuse older acceptance.
