# Distinguish milestone checkpoints from verified staging delivery

Preserve the proposed milestone and goal release distinction for exact amendment review before adoption. Milestone publication records tested staging revision, checkpoint commit, checks and attribution on the shared issue branch. A checkpoint grants no goal-integration authority.

Retain distinct observations for independent review, exact-head hosted gates, staging merge and checks of actual merged deliverables. Show running, failed and unavailable post-merge verification distinctly. Claim verified staging only after required checks pass; production delivery remains separate.

Reconcile uncertain effects before retry. Pre-merge correction reuses the existing PR with refreshed acceptance. Failed post-merge checks retain the observed merge and link correction through the ordinary task path.

## Success measures

- Milestones publish attributable checkpoints while the goal retains one staging delivery.
- Post-merge evidence identifies the actual merge and deliverables.
- Failed or unavailable checks prevent a verified-staging claim.
- Corrections preserve historical merge and failure observations.
