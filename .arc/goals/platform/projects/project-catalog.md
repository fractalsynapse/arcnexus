# Keep project selection verified and isolated

Register projects through authorized canonical repositories and retain verified commits and credential references. Provision absent managed checkouts only within trusted bindings. Keep read credentials, publication grants and execution assignments distinct. Imported declarations cannot replace trusted runtime composition.

Refresh catalog revisions without changing active executions' captured authority or losing accepted revisions. Carry selected project identity through navigation, resource requests, commands, caches and subscriptions. Distinguish registration from reachability.

Removal disables selection and routing while retaining Git and run evidence. Project switching closes old subscriptions; no reachable project produces an explicit unselected state.

## Success measures

- Public and private imports verify exact repository and commit identities and refuse unauthorized bindings.
- Secrets remain outside URLs, events and agent inputs.
- Project switches cannot reuse another project's data or cursors.
- Refresh and removal preserve execution provenance and evidence.
