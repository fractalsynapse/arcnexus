## Findings

Research question: Does TypeScript’s current strict compiler option enable noUncheckedIndexedAccess?

Consultation date: 2026-11-17. Provenance: Direction research activation requested by direction/documentation for milestone direction-research-archive, captured project revision a8ed1fb3ced68ed549d3eddf9311acba9733e801. This report synthesizes the official documentation consulted directly; no compiler experiment was performed.

The strict reference describes a family of checks, rather than every available checking option. The noUncheckedIndexedAccess reference shows that enabling this separate option adds undefined to reads of undeclared properties covered by index signatures, while declared properties retain their types. [strict reference](https://www.typescriptlang.org/tsconfig/strict.html), [noUncheckedIndexedAccess reference](https://www.typescriptlang.org/tsconfig/noUncheckedIndexedAccess.html).

The TypeScript 4.1 release notes explicitly confirm that strict does not automatically enable this flag and describe its effect on array indexing. Configure compilerOptions with both "strict": true and "noUncheckedIndexedAccess": true. [TypeScript 4.1 release notes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-1.html).

## Applicability

Applies to the current official documentation consulted on 2026-11-17. noUncheckedIndexedAccess was introduced in TypeScript 4.1; earlier versions do not support it. The rolling TSConfig pages do not pin this finding to an exact latest compiler release. Keep strictNullChecks enabled for meaningful undefined diagnostics; strict enables it unless individually overridden. Evaluate the effective configuration, including inherited settings and overrides: strict alone does not establish whether noUncheckedIndexedAccess is enabled elsewhere. These are static checks, not runtime bounds enforcement. Recheck the documentation when upgrading because strict’s family may evolve.
